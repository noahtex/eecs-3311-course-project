## Unresolved implementation discrepancies and submission decisions

These diagrams describe the limitations rather than drawing unimplemented functionality:

1. **Observer coverage:** direct profile/resource/window/catering configuration bypasses `applyChanges`; callback task validation omits other-event workload. Reapproval may leave old review warnings. No automatic plan reconciliation after blueprint switches.
2. **Transaction boundary qualification:** facade `mutate` places `operation.get()` before its inner save/capture exception handler. Save/post-operation capture failures restore `before`; arbitrary operation exceptions are not covered by a universal rollback catch. The diagrams deliberately narrow broad “transaction” language in older documentation. This is source inspection, not a newly executed failure-injection finding.
3. **Time, money and editing:** no event ZoneId/DST policy; actuals/reports lack historical currency identity; granular blueprint/idea/task/session/allocation/venue editing remains incomplete. The new UML does not invent those fields/methods.
4. **External functionality:** no weather service, venue booking/selection confirmation, independent provider verification, communication publication or general-language FAQ. F07–F10 feature-schema validation is outside the shared malformed-output retry callback.
5. **Team reverse links:** Event retains its team, while team has a separate event list. `EventService.createEvent` does not populate that reverse list automatically. The diagrams show both structures without promising automatic synchronization. This is not repaired in a documentation-only task.
6. **Historical report links:** Stage 1 reports continue to reference original UML because reports were explicitly protected from edits. Use the new [Stage 2 index](diagrams/stage2/README.md) when assembling the final submission. Original diagrams remain valid as historical proposals, not as descriptions of final code.
7. **Rubric/tool format:** no official Stage 2 rubric was found in the reviewed repository. Confirm whether UMLet `.uxf` is mandatory. The provided `.puml` files are editable UML sources, but were not converted back into UMLet. Full GUI widget trees, every record field, every exception class and every optional error path are intentionally outside these focused views.

No known invented class/method or unresolved source mismatch remains in the selected Stage 2 diagrams after these stated abstractions. The implementation gaps above remain open; this task made no code repairs or report edits.
