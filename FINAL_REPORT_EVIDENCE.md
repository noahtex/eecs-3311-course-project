## 3. Five implemented design patterns

**MVC:** `Event`, `Task`, `Schedule`, `Budget` and related records are the model. `EventPlanningCLI` and the `Dashboard` feature panels are views. `EventPlanningController` receives operations such as `fuseIdeas`, `generateTasks`, `approveBudget` and `confirmChange` and delegates to the facade. For example, `IdeasPanel` calls controller `fuseIdeas`, facade coordinates the agent and stores concepts through `EventService`, then the view renders them. GUI parsing/formatting and confirmation are view concerns; deterministic planning checks live in services. The implemented GUI replaces Stage 1's proposed single `EventPlanningGUI` class with a dashboard/session/panel composition.

**Facade:** `EventPlanningFacade` exposes the application use cases over `EventService`, `EventPlanningAgent`, task/schedule/budget services, adaptive service, tools and repository. For example, `generateBudget` gathers catering evidence and AI proposals, while `approveBudget` delegates validation/storage to `BudgetService.saveBudget`. Views do not coordinate those dependencies. `mutate` serializes mutations, captures state, saves meaningful changes and restores prior state on failure; `persistent` wires the production store. `close` releases owned services/resources.

**Strategy:** `PlanningStrategy` declares `name` and `buildGuidance(Event)`; `fromName` selects `BudgetPriorityStrategy`, `CommunityPriorityStrategy` or `AttendancePriorityStrategy`. Facade generation selects the strategy via agent `setPlanningStrategy`. The agent incorporates `buildGuidance` into blueprint/budget prompts: spending/reserve, inclusion/relationships, or reach/capacity. These are interchangeable planning guidance policies, not three independent optimization algorithms or guarantees of better outcomes.

**Observer:** `Event` is the subject, `EventObserver.onEventChanged(Event, Set<String>)` is the contract, and `TaskService`, `ScheduleService`, `BudgetService` are concrete observers. Facade `subscribe` calls event `addObserver`, including after persistence restoration. Formal F08 confirmation reaches adaptive `confirm` → event `applyChanges` → observer callbacks. Services recheck retained plans and call `flagReview`; they do not silently regenerate/approve replacements. Ordinary configuration setters bypass this notification path, and the task observer supplies an empty other-event workload list. Blueprint-switch warnings are set directly and do not prove universal Observer coverage.

**Adapter:** the agent depends on target `AIModel.generate(String)`, rather than the Google SDK. `GeminiAdapter.generate` translates that call to adaptee `GeminiAPIClient.generateContent`; the latter handles Google GenAI SDK requests/configuration and safe failures. `close` delegates lifecycle cleanup. Injected `AIModel` fakes exercise workflows without network requests. Separately, `AITool.execute` abstracts `VenueSearchTool`/`CateringSearchTool` over Places; the primary Stage 1 Adapter evidence is the `AIModel`–Gemini chain.

## 4. Changes from Stage 1 design to current implementation

- **Executable shared application:** Stage 1 feature specifications/UML became Java services, structured immutable planning records, a controller/facade, real Gemini integration, deterministic validators and JUnit tests. Runtime targets Java 21; `pom.xml` pins JavaFX 21.0.9, Google GenAI SDK 1.80.0, Jackson databind 2.18.11 and JUnit Jupiter 5.11.4. These are repository versions, not claims about current external releases.
- **Blueprint approval:** pending `selectedBlueprintId` is distinct from `approvedBlueprintId`. Selecting another option does not replace execution approval. F03/F04 use only `executionBlueprints()`' approved alternative. Alternatives without approval block new task/schedule generation; events with no alternatives retain an explicitly labelled event-details-only fallback. Switching approval retains existing plans/drafts and flags manual review. Legacy version-1 JSON missing the two new fields loads with null references without automatic approval or immediate rewriting.
- **JavaFX dashboard:** `App`, `Dashboard`, `GuiSession` and individual panels implement all ten features, replacing the planned monolithic GUI class. Background serialized JavaFX tasks keep network/storage work off the UI thread; calendar inputs, readable names, provider evidence, confirmation dialogs and Planit branding were added. The independent CLI shares controller/facade behavior. The November 16 Maven change passes Windows console input directly to the separate CLI JVM using `inheritIo`.
- **JSON persistence:** `storage/PlanRepository`, `JsonPlanRepository`, `PlanData`, `PlanDataMapper`, `StorageJson` and `AppDataDirectory` replace session-only production storage. Both launchers load the same configurable local store. Successful mutations save stable IDs, nested records, drafts, approvals, pending proposals and reports. Exclusive OS locking, digest checks, flushed temporary replacement, semantic validation and facade rollback protect writes; corrupt input fails startup rather than resetting data. No automatic backup history or encrypted store exists. Tests use temporary synthetic stores.
- **Venue/catering research:** `PlacesAPIClient` supplies actual Google Places Text Search (New) listings through the two tools. Evidence distinguishes reported facts, estimates and unknowns. Deterministic venue fit/ranking complements AI narrative. Manual candidates support fallback. The planned weather tool is not implemented; no booking or supplier availability verification was added.
- **Approval workflows:** tasks/schedule/budget have separate drafts with revise/approve/discard operations. F08 separates proposal/simulation from confirmed real changes. Communications require review/approval and revert to draft after editing or relevant event changes. F10 saves confirmed actuals before analysis. These safeguards do not establish full semantic correctness of AI output or user edits.
- **Deliberate scope differences:** `ScenarioResult` replaces the proposed simulated blueprint; F09 FAQ uses local whitelisted facts; monetary calculations use decimal amounts where represented, but historical currency and timezone support remain incomplete. General concept/blueprint and granular collection editing were not completed.
